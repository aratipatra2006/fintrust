# FinTrust — UI icons and chatbot production fix report

## Findings and changes
- Confirmed: runtime_guard.py omitted font-src, so default-src 'self' blocked external fonts. The original Font Awesome 6.4.0 stylesheet was https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.4.0/css/all.min.css. Its solid font URL is https://cdnjs.cloudflare.com/ajax/libs/font-awesome/6.4.0/webfonts/fa-solid-900.woff2; regular and brands use fa-regular-400.woff2 and fa-brands-400.woff2 under the same directory. Google Fonts uses fonts.gstatic.com; the precise request from production is not known because the console URL was redacted. The old local SVG fallback was only included in the lender workspace, and four Free-unsupported icon names were found. No local font files existed in the original static directory.
- Bundled Font Awesome Free 6.7.2 with original license, local CSS/fonts and SVG assets. All affected templates reference the same bundle and conditional fallback. Fallback includes the direct private-use chevron pseudo-element in components.css. Replaced fa-sparkles with fa-wand-magic-sparkles, fa-bell-ring with fa-bell, fa-shield-check with fa-circle-check or fa-shield-heart as appropriate, and fa-shield-exclamation with fa-triangle-exclamation. Explicit CSP font-src allows only self and fonts.gstatic.com. Restricted stylesheet and script origins to the ones found in the project; preserved inline scripts/styles required by existing templates, HTTPS image/connect policies, and other security headers. Added object-src none and base-uri self.
- Confirmed chatbot used Gemini only (no Groq integration found). POST /chat uses JSON message and streams SSE. Original 60s provider timeout and three retries could exceed Gunicorn's 120s timeout; provider exceptions were converted to ValueError but route caught different types. Provider calls were lazy, so errors could arise after 200 headers. DB metrics were queried even for greetings. These are confirmed defects, NOT proof of the actual production 502 trigger; Render/Gunicorn logs, actual credentials, DB connectivity and provider project access were not supplied.
- Patched provider with typed safe errors, 4s connect and 15s chatbot read timeouts (20s cap for other calls), one retry by default (maximum two configurable), capped backoff, no redirects, explicit stream completion detection, and a best-effort 35s stream iteration deadline. Requests read timeout is an inactivity timeout, not an absolute wall-clock limit. Auth/model errors are not retried. Provider body, keys and exception details are not sent to browser. Existing Gemini model default gemini-3.8-flash retained; verify project access. Other Gemini generate_json callers remain supported. Chat route validates message type/length, serves existing greeting/small-talk fast path without DB, handles database failure, primes SSE iterator before headers, reports pre-stream errors as HTTP JSON and mid-stream errors as SSE, and only stores completed AI replies. Browser reports actual safe server message, handles interrupted stream, preserves space tokens and restores controls in finally. Existing user-scoped conversation history remains in-process as before.
- dashboard.js Category API log prints parsed JSON; history.js loaded transaction count is informational on successful response. No changes to their fetch or rendering logic except valid icon substitutions.
- app.py: environment takes precedence over dotenv; requires non-placeholder secret of at least 32 characters in production, development-only ephemeral fallback; SameSite=Lax default with Secure/HttpOnly maintained; CORS explicit allowlist (no default cross-origin access). Startup database error no longer prints raw exception. Render exposes secret-managed GEMINI_API_KEY and model config; Docker uses UTF-8 requirements directly and excludes private local/demo files and env files. No .env or API key added. Existing model artifacts retained; no database schema changes.

## HTTP contract
400 invalid message; 401 unauthenticated; 503 provider configuration/unavailable or DB unavailable; 504 provider timeout; 502 malformed/unexpected upstream failure; 200 text/event-stream on success. If headers already sent, an SSE error event reports the failure instead of changing HTTP status. JSON errors include status, error, message, request_id. Reverse-proxy generated non-JSON errors are handled by the browser.

## Deployment checklist
1. Back up existing repository and database. Extract ZIP to clean project folder; review diff. Keep production secrets in Render environment, never commit .env. Preserve existing DATABASE_URL and SECRET_KEY to avoid invalidating sessions; ensure key is strong (32+ chars). Set GEMINI_API_KEY (or GOOGLE_API_KEY if managing manually), GEMINI_MODEL=gemini-3.8-flash, GEMINI_MAX_RETRIES=1, SESSION_COOKIE_SECURE=true, SESSION_COOKIE_SAMESITE=Lax, FINTRUST_ENV=production. Set CORS_ORIGINS only if a separately hosted trusted browser frontend is actually required; same-origin needs none. Set FORCE_HSTS=1 only after confirming HTTPS and subdomain readiness.
2. In Python 3.12 environment: `python -m pip install -r requirements.txt pytest`; run `python -m pytest -q`. Run `python test_gemini.py` with real key configured via environment to check actual project access; never paste key into source. Test against staging PostgreSQL and opt-in provenance integration tests only with isolated test DB. For a local HTTP session use SESSION_COOKIE_SECURE=false and FINTRUST_ENV=development; never use these settings in production.
3. `docker build -t fintrust:patched .` then `docker compose up --build` with configured private .env. Verify /health and /ready. Review build output for dependencies and model compatibility.
4. Commit changes, including vendor assets and necessary existing ML .pkl files (the original .gitignore ignores *.pkl; if new to Git, explicitly add required models after confirming provenance). Push to existing Render deployment branch; deploy latest commit, inspect logs and /ready. Worker configuration stays unchanged. For existing Render services, set env variables manually if Blueprint sync is not automatic. Do not create duplicate production service unintentionally.
5. Hard refresh, open DevTools > Network > Disable cache, reload. Verify local Font Awesome CSS, WOFF2 200 and font/woff2 MIME; inspect CSP response header and console. Verify every borrower, admin and lender screen, dropdown chevron, hover, history status icons, chat FAB, notifications. Block local WOFF2 and TTF via browser request blocking, reload, confirm SVG fallback; unblock after test. Google fonts should load only from allowed origin. Check category chart and history with authenticated known data. Check payment QR/OTP and login/OAuth as regression smoke tests.
6. Chat: send hello, budget question, and general query such as Explain compound interest (provider path). In staging only, remove/invalid key to check 503 structured response, simulate upstream timeout/503, confirm UI restores send button, no false success. Restore staging key. Compare request_id and timestamps against Render logs; look for worker timeout, DB connection issue or upstream HTTP status. If 502 persists, collect sanitized logs, route status, timing and request ID; never share keys, cookies or financial records.

## Remaining production risks
In-process conversation memory and rate limits are per worker, not shared or durable; Redis or equivalent needed for consistent multi-worker state/rate limiting. Existing inline CSP allowances, broad HTTPS img/connect origins, external QR/chart scripts and lack of comprehensive application-wide CSRF audit remain security-hardening work; do not claim full security certification. Validate Google OAuth and any legitimate cross-origin integration after cookie/CORS change. Third-party model availability, quota, billing, privacy review for financial data sent to Gemini and PostgreSQL migrations must be checked in the actual deployment. Existing project dependency/ML compatibility and live production behavior are not established by the static tests.
